# guysfall · 当前实施设计

本文件统一维护玩法、实现契约、验证状态和待办。当前目标是一个完整的七日航程：World 产生处境与处理办法，宿主根据玩家派遣选择隐藏干扰，普通船员按规则执行。玩家通过人手、手牌、维护、调查、监工和放逐做决定。不增加玩家面对的模型来源说明、加工链或人物养成指标；先根据实际试玩推进玩法，不做收益对照实验。

## 玩家规则

八名固定船员，四人当值轮换，七日航程，一个随机隐藏宿主。三项公共资源为氧气、电力、物资；新航程初始各 75，上限各 100。监察官每日精力 3。资源归零失败，撑过七天或正确放逐宿主获胜。

一名人物只能承担一项派遣，一张手牌只能交给一名执行者。休班船员参加系统或事件任务需要调遣令，休班谈话花 1 精力。监工花 2 精力，保护任务所在系统本日免受宿主隐藏干扰，不增加产出，也不阻止普通领用；因此每天只能重点保护一个系统。放逐花 1 精力，猜错永久失去一名船员及其岗位，猜对立即结束。

系统位置有两种行动：维护花 2 物资、基础恢复 12，逐日减少 0.4，岗位专长影响实际恢复；调查占用同一份人手，核对之前日期的未检查痕迹，本次不恢复资源、不收维护费用。设备每级损伤增加每日消耗 1。基础日耗为 7，每两日增加 1；前三项资源分别扣除其日耗和设备损耗。

新事件给两种互斥办法，每种最多两个人，没有额外专业门槛。办法可花物资、投入已有手牌、承担另一项资源损失、先调查或直接接受损失结束问题。费用和收益写在规则字段里，服务端执行，不能用描述代替实际效果。当前没有疲劳、士气、独立加工、物品库或永久组件玩法。

World 可提供有逾期损失的危机，也可提供限时机会；新提交必须明确 1–3 个可处理日及 0–12 点逾期代价。代价为 0 时可以主动放过，到期只关闭机会，不扣资源、不另生待办。开场从第一日计算，日结新事件从次日计算，终日截断。机会使用绿色标记，办法页及提交预览明确显示「错过不扣资源」。

事件奖励可包含临时调遣令，使之后一日能调遣额外休班船员；仍占用人物和手牌，不增加当值人数、不自动替玩家安排。玩家可在同一处置中先花材料腾出手牌位，再收下奖励；满手时奖励仍按已有规则折算 2 物资，办法页显示这一条件。奖励不必只恢复资源，World 可围绕现有手牌及人手提出不同取舍，但不要求固定题材轮换或危机/机会配额。

## 真实生成与事件收尾

真实模式新航程先进入 `opening`：World 读取初始船况，生成恰好一件选择事件；成功后进入第一日布牌，不执行日耗、宿主行动或普通派遣。开场生成失败不会混入固定内容，也不会替换原航程。服务器在开场期间锁住其他结算和开新局请求。没有现存航程时，已配置模型默认进入真实模式；未配置时进入固定策略演练。

固定策略模式保留氧气泄漏和冷库开场，以及可复现的少量生成样本，只用于离线试玩和规则回归。真实模式的开场与后续新事件均由 World 提交；资源扣减、派遣合法性和行动痕迹仍由服务端裁定。宿主和 World 失败均不以脚本内容兜底。

World 只接收公开船况、近三日公开结果、历次选择、已公布发现、手牌与上限、船员当值情况、已有事件、后续队列和操作痕迹，不接收宿主身份或私有动作。历史选择是背景，无需每件事都写成上一件事的续单。资源未耗尽、当前日小于 min(6, 航程天数)、当日未提供选择、有空位且未积压两件选择事件时，请求恰好一个新事件；其余只总结。开场占用第一日的生成名额，第六、七日不再新增独立事件。总容量六件，排队后续计入容量，期限不超过终日。

处置或到期后记录 `event_closed`，同一事件只能预留一层明确后续，后续必须直接结束。只执行所选分支的后续，满台时排队，期限从实际入台开始。新生成不能重复已结束标题，也不能引用已结束事件的选择、处置报告及其衍生记录来换名重开。该限制复用已有记录及来源关系，不建立通用事实系统；它不能机械证明两个使用不同新来源的描述在语义上毫无重复。

模型工具只要求当前玩法使用的字段，省略已停用的专业门槛、组件、实物、加工操作、永久标志和额外测试耗电。服务端只为这些省略字段补固定的 none/0，再进行完整规则校验；不会补写题材、选择或奖励。若模型仍提交这些字段，只有固定值可通过。路线 ID 最长 48 字符，按钮名称最长 18 字符，格式错误反馈含具体长度界限。

每件事至少有一种直接结束的办法、至少一种不花材料或物资的办法。两种办法必须在人手、材料、费用、资源损失、调查机会或后续负担上有区别，仅换名称或奖励无效。奖励值为恢复总量 + 修复级数×4 + 手牌×4，上限为 16 + 额外人手×5 + 材料×6 + 物资费用。各项 `loss` 为 0–12，不增加奖励预算。人手、费用、奖励和材料在提交与执行时分别校验，整组只结算一次。

## 调查、证据与宿主

事件的 `inspect + discovery` 可以先查再决定：调查公布 finding，保留同一事件 ID，换成两种新办法，至少留到下一日；此前 finding 和新办法只留服务端。调查分支不挂后续，新办法和预留后续都是叶子，不再调查或续接任务。最后一天禁止需要次日处理的调查办法。该机制的开放内容仍由 World 生成，不强制每件事件都包含调查。

系统调查、事件调查及 discovery 完成时会核对相关系统往日痕迹。痕迹来自真正发生的隐藏操作，不由 World 编造责任人；当天操作次日起可查，每条痕迹只公布一次。公开内容包括操作日期、系统、方式和接触范围，不直接公布操作者或宿主身份。接触范围表示机会，不能单凭一次记录定罪。

未外派时的接触范围：科学家、工程师、医官接触供氧；安保官、通讯员、书记员接触供电；仓储官、厨师接触物资。派往有系统关联的任务后，只接触任务所在系统；谈话保留原值守范围。人物悬停可查看值守范围。死亡人物不进入当天范围。

宿主每日主动额度 8，只能干扰当前可接触系统。全部公开工作完成后才结算隐藏行动：damage 扣资源并增加损伤，consume 扣资源，frame 扣资源并把目标加入低可信登记。监工阻止成功操作，宿主可选择 none 收敛；它读取接触范围、监工和玩家安排后决策。伪造登记明确提示可能不可靠，推理助手不会用它排除范围外的人或形成集合交集定罪。

普通人类也可能发生 1–3 点未登记领用，造成匿名异常。谈话可以确认谈话者自己真正发生的往日小额领用，帮助解释噪声；只公开本人记录，不提供猜测证词。宿主可保留自己的领用记录，也可用小额领用混入噪声。规则事实只通过公开证据记录进入玩家和 World 上下文；旧私有目击、位置声明和人物记忆不会自动变成当前线索。

旧格式普通事件调查仍会产出应急氧罐或备件，满手折算 2 物资。操作许可可以修复一级损伤并移除该旧事件；调查委托把普通派遣改为调查；一次承诺用于非路线任务后换备件。药箱与氧罐用于相关维护恢复。新事件通过自身机械字段决定材料用途和奖励。

## Agent、界面与存档

普通船员按规则执行，不请求模型；模型只用于宿主和 World。通常每轮两次逻辑决策，加一次开场 World 决策。参数错误最多纠正一次，429/5xx、网络失败或超时最多尝试三次。失败整轮回滚；已经成功的决定以完整请求及模型配置签名缓存，改计划时失效。所有人物决定齐备后才公布回报进度，避免完成速度暴露身份。

主界面为 Phaser + TypeScript 单桌面，只读玩家投影，保留人物与手牌的点击、拖放、唯一投入、提交预览、监工预算、结果分页和草稿刷新恢复。调查在岗位筹码、人物牌、提交预览和报告中明确显示。航程报告顶部显示三项储备，左侧显示执行者、任务和本次资源增减，右侧以记录卡呈现回报与调查发现；结局报告沿用同一布局。航程记录保留「派遣与船况」和「操作痕迹」两页签，每条卡片分开呈现标题、日期、地点、正文、人物名单及资源变化；同一天相邻的三项日常损耗合成一张卡。人物名单使用中性色肖像筹码，资源增加用绿色、减少用红色，登记异常单独显示「登记存在不一致」。按实际换行高度分页，长内容保留全文和续页上下文，无障碍文本同步包含卡片内容。报告与历史回报可以直接跳到对应的公开痕迹。

服务端投影以 `notes` 和 `factIds` 拆开回报文字与已公布事实，只关联原回报确实包含的事实，不改存档与命令；旧回报缺少字段时沿用原文字。日志只展示具体行动、发现与资源变化；监工、路线完成及日结不复述操作规则、不追加固定人物尾句；空白页只显示无记录状态。操作规则放在帮助页、任务说明和提交预览。World 的摘要和事件描述遵守同一文案边界。旧存档已知的固定说教尾句在玩家投影及 World 公开上下文中清理，迁移说明不进入日志；原始存档与事实数据保留。美术来源和映射继续见 `docs/art/资产说明.md`。

录制结构 v3，当前 runtime 为 `event-opportunities-v9`，包含可重放的开场命令和事件期限。v7/v8 经快照哈希校验后作为基线导入，保留原有玩法状态，再按 v9 记录和重放新命令；不把旧历史标为新版本完整回放。旧命令未提交期限/代价时沿用当时原型默认值；新模型必须提交，不由代码补写。v6 及更早 runtime 沿用原有基线迁移。旧设备和实物逐件换为备件，满手每件补 2 物资；复杂待办改为两种直接办法，保留期限与来源；清除对应失效草稿。旧航程保留原有资源与规则数值，缺少新痕迹字段的旧操作不补造线索。体验新开场、75 储备及 2 精力监工需要开始新航程。

## 待办与已知边界

1. 本局已出现三件真正可错过的机会，但处置仍围绕资源与手牌。氧气/电力终局均接近 90，生存压力偏轻；下一步应通过实际试玩调整人手与收益取舍，不能仅凭新事件名称或一条成功航程宣称可玩性已经解决。
2. 这局真实事件均采用直接处置，未走模型生成 discovery 或预留后续；二者由自动检查和既有浏览器回归覆盖。真实航程取得了调遣令，额外人手由自动检查及浏览器固定策略实测验证；不能说该真实航程已花掉新奖励。宿主全部策略及真实玩家正确放逐难度尚未覆盖。
3. 接触范围与普通领用提供可推理的信息，但还未验证真实玩家的正确放逐难度。当前没有自动向玩家推荐嫌疑人。资源紧张程度及手牌用途仍需多次实际试玩，单条成功航程不等于已证明好玩。
4. 关闭来源能阻止同一结果直接续单；使用新来源但语义重复的维修问题仍可能出现。遇到具体重复再补必要约束，不把全面事实证明体系作为本阶段前置工程。
